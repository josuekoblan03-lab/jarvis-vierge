# Mémo S4 — Lire et piloter du code

## Ce que j'ai appris
- Un prompt flou donne un résultat flou. Les **4 ingrédients d'un bon prompt** :
  1. **Contexte** — sur quoi je travaille
  2. **Objectif** — ce que je veux
  3. **Contraintes** — comment, avec quels outils
  4. **Résultat attendu** — à quoi ça ressemble si c'est réussi
- Je **lis ce que Claude fait** (quels fichiers il touche). Je ne valide pas en aveugle.
- Si je ne comprends pas, je demande à Claude d'expliquer avant d'accepter.
- Je construis **par petites touches**, je vérifie dans le navigateur à chaque fois.
- Face à une erreur : je **copie le message** et je le donne à Claude.

## Prompt type (4 ingrédients)
> « Dans mon app Next.js (contexte), crée une page de connexion (objectif), avec Tailwind et un champ email + mot de passe (contraintes). Je veux voir un formulaire centré qui s'affiche sans erreur (résultat attendu). »

## Réflexe quota (Pro)
Petites touches claires = moins cher qu'un gros prompt confus refait 3 fois.

## Mon devoir
Ajouter seul une petite page ou un élément à mon app, avec un bon prompt. Noter une question si je bloque.
