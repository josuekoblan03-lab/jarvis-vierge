# Mémo S14 — Hooks et garde-fous

## Ce que j'ai appris
- Un **hook** = une règle automatique déclenchée à un moment. Mon Jarvis en a déjà :
  - **dangerous-command-blocker** : bloque les commandes destructrices.
  - **secret-scanner** : m'empêche de committer une clé.
  - **blocage .env** en écriture : protège mes secrets.
  - **formatage auto** (prettier/black) après édition : code propre sans y penser.
  - **scope-guard** : me prévient si je modifie des fichiers hors du périmètre prévu.
- Ces garde-fous rattrapent les erreurs classiques de débutant.
- Mais la **discipline reste la base** : clés dans `.env`, jamais dans le chat ni en dur.

## Vérifs utiles
```
git status        # mon .env ne doit PAS apparaître (il est gitignored)
```

## En cas de blocage légitime
Si un hook bloque une commande correcte (faux positif), je **reformule** plutôt que de désactiver le garde-fou.

## Réflexe quota (Pro)
Les hooks sont locaux : ils ne consomment pas de quota Claude.
