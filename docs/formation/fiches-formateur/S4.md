# Fiche formateur — S4 : Lire et piloter du code

**Objectif :** l'apprenant sait écrire un prompt efficace, lire ce que Claude produit, repérer un problème et faire corriger. Résultat : une première vraie page de son app en local.

---

## Déroulé (2 h)

### 0-10 min — Retour devoir
- A-t-il réussi `/reprendre` seul hier ? Débriefer les éventuels ratés (souvent : mauvais dossier).

### 10-35 min — Concept : le bon prompt
- Un prompt flou = un résultat flou. Les 4 ingrédients : le **contexte** (sur quoi), l'**objectif** (quoi), les **contraintes** (comment/avec quoi), le **résultat attendu** (à quoi ça ressemble si c'est réussi).
- Montrer un prompt vague vs un prompt précis sur la même tâche, comparer les résultats.
- Apprendre à lire la sortie : Claude dit ce qu'il fait (lit tel fichier, modifie tel autre). Ne pas valider en aveugle.
- Règle : si tu ne comprends pas ce que Claude a fait, demande-lui d'expliquer avant d'accepter.

### 35-50 min — Démo : itérer sur une page
- Démo : « crée une page d'accueil avec un titre et un bouton ». Puis itérer : « le bouton doit être centré », « ajoute un sous-titre ». Montrer qu'on construit par petites touches.
- Montrer comment pointer une erreur : copier le message d'erreur du terminal/navigateur et le donner à Claude.

### 50 min-1 h 50 — Pratique
1. L'apprenant prend la prochaine étape de son plan (une page concrète de son app, ex. la page principale).
2. Il écrit le prompt avec les 4 ingrédients. Le formateur relit le prompt AVANT qu'il l'envoie.
3. Claude code. L'apprenant lit la sortie, lance `npm run dev`, regarde dans le navigateur.
4. Il itère 2-3 fois pour ajuster (texte, disposition).
5. Si erreur : il copie le message et le donne à Claude. Apprentissage du cycle erreur → correction.
6. PROGRESS.md mis à jour, commit.

### 1 h 50-2 h — Récap + checkpoint + devoir
- Récap : prompt en 4 ingrédients, lire la sortie, cycle d'erreur.
- **Devoir** : ajouter seul une petite page ou un élément à son app, en écrivant un bon prompt. Noter une question s'il bloque.

---

## Points de vigilance
- Il va vouloir accepter tout ce que Claude propose sans lire. Le freiner : « qu'est-ce que Claude vient de changer ? ».
- Ne pas le laisser empiler 10 demandes d'un coup. Une touche à la fois, on vérifie, on continue.
- **Économie Pro** : itérer par petites touches claires coûte moins qu'un gros prompt confus qu'on refait 3 fois.

## Démo possible sur un vrai projet
Montrer un bug réel que tu as corrigé en donnant le message d'erreur à Claude : dédramatiser l'erreur.

## Critère de réussite
Une page de son app s'affiche dans le navigateur, et l'apprenant a corrigé au moins une erreur par lui-même.
