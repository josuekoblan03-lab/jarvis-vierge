# Fiche formateur — S1 : Prise en main

**Objectif de la séance :** l'apprenant a Claude Code qui tourne sur le Jarvis Vierge, comprend ce qu'est un terminal et Git à son niveau, a eu sa première vraie conversation, et a rempli son CONTEXT.md + CLAUDE.md.

**Pré-requis apprenant :** avoir installé Node.js, Git, Claude Code, avoir son abonnement Pro actif. Lui envoyer la liste 2 jours avant.

---

## Déroulé (2 h)

### 0-10 min — Accueil et cadre
- Expliquer le fil rouge : « dans un mois tu auras une app en ligne que TU auras construite ».
- Poser la règle n°1 : **c'est toi qui tapes**. Moi je montre une fois.
- Montrer le dossier `jarvis-vierge/` : « c'est ton atelier, tout est déjà dedans ».

### 10-35 min — Concept : terminal + Git (le minimum vital)
- Démo : ouvrir un terminal, `cd`, `ls`, `pwd`. Faire refaire.
- Git en 3 idées : un dépôt = l'historique de ton projet ; `git status` = où j'en suis ; un commit = une photo sauvegardée. Pas plus pour aujourd'hui.
- Démo : `git status` dans le Jarvis Vierge.
- **Piège à montrer** : ne pas avoir peur du terminal, lire ce qui s'affiche. 90% des blocages = on n'a pas lu le message.

### 35-50 min — Démo : première conversation Claude Code
- Lancer Claude Code dans le dossier.
- Montrer une conversation simple : « explique-moi ce que contient ce workspace ».
- Montrer la différence entre demander (chat) et faire faire (Claude agit, lit des fichiers, propose).

### 50 min-1 h 50 — Pratique
1. L'apprenant ouvre Claude Code dans `jarvis-vierge/` lui-même.
2. Il copie `.env.example` en `.env` (on laisse vide pour l'instant, on remplira en S9).
3. Il remplit `context/CONTEXT.md` (qui il est, objectifs) en dialoguant avec Claude si besoin.
4. Il édite `CLAUDE.md` sections « Qui je suis » et « Comment tu dois m'aider ».
5. Il lance `/prime` et lit le résumé que Claude fait de lui. On corrige ensemble si Claude a mal compris.
6. Il fait son premier commit : `git add -A` puis `git commit -m "mon contexte"`.

### 1 h 50-2 h — Récap + devoir
- Récap : terminal OK, Git OK, `/prime` OK, contexte rempli.
- **Devoir** : réfléchir à l'app qu'il veut construire (problème réel, pour qui, 3 fonctions max). L'écrire en 5 lignes.

---

## Points de vigilance formateur
- Ne pas noyer sous Git. 3 commandes suffisent aujourd'hui.
- S'il bloque à l'install, prévoir 20 min de marge (c'est fréquent). Ne pas installer à sa place : le guider.
- **Économie Pro** : lui faire remarquer qu'on est resté sur Sonnet, que la session était courte. Premier réflexe.

## Démo possible sur un vrai projet
Montrer rapidement un de tes projets existants avec son `PROGRESS.md` : « voilà où on va, un projet qui se reprend tout seul ». Ne pas détailler, juste donner envie.

## Critère de réussite
L'apprenant relance Claude Code seul, tape `/prime`, et Claude le reconnaît via son CONTEXT.md.
