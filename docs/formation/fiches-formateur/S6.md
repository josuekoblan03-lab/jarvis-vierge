# Fiche formateur — S6 : Design avec Claude Design, puis code

**Objectif :** l'apprenant maquette l'interface de son app dans **Claude Design** (le design vient en premier), puis la transpose en code (Next.js + Tailwind) dans Claude Code. Il apprend à décrire un visuel et à faire un handoff design → code propre.

**Méthode clé de cette séance :** on ne code PAS l'UI à l'aveugle. On la dessine d'abord dans Claude Design, on valide le visuel, ENSUITE on le transpose en code.

---

## Déroulé (2 h)

### 0-10 min — Retour devoir
- Il relit ses phrases sur les 6 briques. Corriger les contresens.

### 10-35 min — Concept : pourquoi designer avant de coder
- Le piège : demander du code UI directement → on itère visuellement DANS le code, c'est lent et coûteux en quota.
- La bonne méthode : **Claude Design d'abord**. On obtient une maquette qu'on regarde, qu'on ajuste vite, avant d'écrire une ligne de code.
- Une fois le visuel validé, Claude Code le **transpose** en Next.js + Tailwind fidèlement.
- Décrire un design à Claude : ambiance (3 adjectifs), référence (« comme Stripe », « épuré »), couleurs, disposition. Claude Design ne devine pas le goût.
- Les skills du Jarvis qui aident à la transposition fidèle : `frontend-design`, `ui-design-system`, `tailwind-patterns`, `theme-factory`.

### 35-50 min — Démo : le cycle design → code
- Démo : décrire la page d'accueil, la faire maquetter dans Claude Design, ajuster (couleur, disposition), puis demander à Claude Code de la transposer en page Next.js + Tailwind. Montrer que le code colle à la maquette.

### 50 min-1 h 50 — Pratique
1. L'apprenant choisit l'ambiance de son app (3 adjectifs + éventuelle référence).
2. Il **maquette dans Claude Design** sa page principale. Il itère sur le visuel (couleurs, titres, boutons, espacements) AVANT de coder.
3. Quand le visuel lui plaît, il demande à Claude Code de **transposer** la maquette en code Next.js + Tailwind (en s'appuyant sur les skills de design).
4. Il compare le rendu codé à la maquette dans le navigateur, ajuste les écarts.
5. Il fixe une cohérence (mêmes couleurs/boutons) pour les pages suivantes.
6. PROGRESS.md + commit.

### 1 h 50-2 h — Récap + checkpoint + devoir
- **Devoir** : maquetter seul une page secondaire dans Claude Design (même ambiance), sans encore la coder.

---

## Points de vigilance
- Bien faire respecter l'ordre : **design d'abord, code ensuite**. C'est contre-intuitif pour un débutant qui veut « voir du code ».
- Éviter de changer d'ambiance à chaque page. Fixer une direction visuelle et s'y tenir.
- Rendu lourd (3D, effets) : sa machine peut ne pas avoir de GPU. Rester sur du 2D propre.
- **Économie Pro** : itérer le visuel dans Claude Design coûte moins que de refaire du code 5 fois. C'est tout l'intérêt du design-first.

## Démo possible sur un vrai projet
Montrer une maquette Claude Design d'un de tes projets et l'écran codé correspondant : prouver que le handoff marche.

## Critère de réussite
L'apprenant a une maquette validée dans Claude Design ET sa transposition codée fidèle, pour sa page principale.
