# Fiche formateur — S10 : Base de données

**Objectif :** l'app lit et écrit de vraies données. L'apprenant comprend un schéma simple (tables, colonnes, relations) et fait un CRUD de base.

---

## Déroulé (2 h)

### 0-10 min — Retour devoir
- Il montre ses 2-3 tables imaginées. On les affine ensemble.

### 10-35 min — Concept : une base de données sans jargon
- Une **table** = un tableur (lignes = enregistrements, colonnes = champs).
- Une **relation** = un lien entre tables (une tâche appartient à un utilisateur).
- **CRUD** = les 4 actions : Créer, Lire, Mettre à jour, Supprimer. 90% des apps, c'est ça.
- La skill `design-database-schema` (commande `/design-database-schema`) aide à concevoir le schéma proprement.
- Démo : concevoir une table simple et l'expliquer.

### 35-50 min — Démo : créer une table + une lecture
- Faire créer une table dans Supabase (via la commande de schéma ou le dashboard), puis une page qui liste ses lignes.
- Montrer la boucle : donnée en base → affichée dans l'app.

### 50 min-1 h 50 — Pratique
1. L'apprenant conçoit son schéma (2-3 tables) avec l'aide de Claude.
2. Il crée les tables dans Supabase.
3. Il implémente la **lecture** : une page qui affiche les données réelles.
4. Il implémente la **création** : un formulaire qui ajoute une ligne.
5. Il teste le cycle complet : j'ajoute → ça s'affiche.
6. PROGRESS.md + DECISIONS.md (noter le choix du schéma) + commit.

### 1 h 50-2 h — Récap + checkpoint + devoir
- **Devoir** : ajouter la mise à jour OU la suppression (le U ou le D du CRUD) sur une entité, seul.

---

## Points de vigilance
- Garder le schéma minimal (pas de sur-conception). On enrichit si besoin.
- Attention au plafond Supabase gratuit : les lectures peuvent être tronquées à 1000 lignes silencieusement. Pas bloquant à son échelle, mais bon à savoir.
- Bien noter le schéma dans DECISIONS.md : c'est une décision structurante.
- **Économie Pro** : faire concevoir le schéma d'un coup (pas table par table sur 10 messages).

## Démo possible sur un vrai projet
Montrer une table réelle d'un de tes projets et l'app qui l'utilise.

## Critère de réussite
L'apprenant ajoute une donnée via son app et la voit s'afficher, depuis une vraie base Supabase.
