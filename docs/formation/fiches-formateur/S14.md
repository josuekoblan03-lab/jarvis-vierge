# Fiche formateur — S14 : Hooks et garde-fous

**Objectif :** l'apprenant comprend les hooks déjà actifs dans son Jarvis et voit comment ils le protègent. Il vérifie que .env est protégé, que le formatage est automatique, et que committer une clé est impossible.

---

## Déroulé (2 h)

### 0-10 min — Retour devoir
- Sa revue de contrôle. Les points sont-ils bien réglés ?

### 10-35 min — Concept : des règles automatiques
- Rappel S5 : un hook = une règle déclenchée automatiquement à un moment.
- Les hooks déjà installés dans son Jarvis :
  - **dangerous-command-blocker** : bloque les commandes destructrices (ex. effacer tout).
  - **secret-scanner** : empêche de committer une clé/token.
  - **blocage .env** en écriture : protège ses secrets.
  - **formatage auto** (prettier/black) après édition : code propre sans y penser.
  - **scope-guard** : prévient quand on modifie des fichiers hors du périmètre prévu.
- Pourquoi c'est précieux pour un débutant : la machine rattrape les erreurs classiques.
- Démo : tenter de committer un faux fichier contenant une clé bidon → montrer le blocage.

### 35-50 min — Démo : formatage auto + commande dangereuse
- Éditer un fichier mal indenté, montrer qu'il est reformaté tout seul.
- Tenter une commande bloquée (ex. une suppression large) → montrer le refus.

### 50 min-1 h 50 — Pratique
1. L'apprenant déclenche volontairement chaque garde-fou pour voir l'effet (clé bidon, commande à risque).
2. Il vérifie que son `.env` réel est bien gitignored (`git status` ne doit pas le lister).
3. Il regarde le contenu des hooks dans `.claude/hooks/` et lit le `settings.json` (sans tout comprendre, juste voir le lien).
4. Optionnel : introduire `hookify` pour créer une règle simple s'il en a l'envie.
5. PROGRESS.md + commit (propre, formaté automatiquement).

### 1 h 50-2 h — Récap + checkpoint + devoir
- **Devoir** : relire son historique git et vérifier qu'aucune clé n'a jamais été commitée.

---

## Points de vigilance
- Les hooks peuvent parfois bloquer une commande légitime (faux positif). Lui apprendre à reformuler plutôt que désactiver.
- Insister : les hooks protègent, mais la discipline (clés dans .env, jamais dans le chat) reste la base.
- **Économie Pro** : les hooks sont locaux, ils ne consomment pas de quota Claude.

## Critère de réussite
L'apprenant a vu chaque garde-fou agir et confirme qu'aucune clé n'est dans son historique git.
